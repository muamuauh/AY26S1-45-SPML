## 0. 为什么先做 Baseline

| 好处 | 说明 |
|---|---|
| **尽早有可交付物** | 不管阶段二的生成效果如何，项目都有一个能演示的产品，整体风险大幅降低 |
| **baseline 本来就要做** | 原计划的 E1（只用真实数据）、E2（+传统增广）就是 baseline，提前做不浪费任何工作 |
| **让增广有的放矢** | baseline 的逐类别错误分析会指出**哪些类别最差**，阶段二只针对这些类别生成，而不是盲目造数据 |
| **Demo 框架复用** | 阶段二只替换模型权重，界面、规则、推理流程全部沿用 |

> ⚠️ **前提**：阶段一开始时就要把**测试集和训练配置固定下来**，否则阶段二的对比不成立（见 [§2.3](#23-两阶段衔接的三条硬约束)）。

> 💡 **仍然成立的两条原则**
> 1. **④ 判断不能省**。感知模型输出的是一堆孤立检测框，项目简介要求的是 `accurately appraise the potential risks`。哪怕是 baseline，也要有一层规则把检测框变成风险等级，否则交付的只是检测器。
> 2. **实验比界面重要**。Demo v1 是阶段一的交付物，但项目题目是 *generative image-based learning framework*——**阶段二的 E3 对比才是立项理由**。

### 2.2 各步骤逐个说明

#### ① 定标准 · Risk Taxonomy ✅ 已完成

> **状态**：线下完成 ｜ **负责**：成员 A

**待办**：把最终版 Taxonomy 提交到仓库（建议 `configs/taxonomy.yaml`，写明每个类别名和判定标准）。它是 ③ 的类别表和 ④ 的规则来源，三方必须引用同一份文件。

#### ② 备料 · 整编公开数据 ✅ 已完成

> **状态**：线下完成 ｜ **负责**：成员 A（全员协助）

进入阶段一前，请确认以下三件事已经落地：

- 🔒 **TelecomEval 已划出并冻结**——这是阶段二对比能成立的前提，之后**任何时候**都不能再动
- `licence_manifest.csv` 已逐张记录 T3 图像的来源与许可（CC BY / CC BY-SA 的硬性义务）
- TG1 的实际张数（TelecomSeed / TelecomEval）已记录到仓库，报告要写 Planned vs Actual

#### ③ 学习 · 训练 Baseline 感知模型

> **输入**：TelecomSeed + T1/T2 公开数据 ｜ **输出**：baseline 权重 + E1/E2 结果 + 逐类别错误分析
> **时间**：W4–W6 ｜ **负责**：成员 C（人员）+ 成员 D（机械）｜ **决策门**：TGB

**范围**：只做 **Workers + Machinery** 两个维度（相当于从一开始就执行 D8）。Terrain 与 Materials 没有现成公开数据、类别定义主观，阶段二视进度再加。

**做法**：

1. **类别统一**：各公开数据集的标签名不一致（`helmet` / `hardhat` / `Hardhat`、`NO-Hardhat` / `no_helmet`……），合并前写一张**映射表**对齐到 Taxonomy 类别。这一步漏掉，模型会学到互相矛盾的标签
2. **模型**：YOLOv11（Ultralytics），COCO 预训练权重微调。baseline 用**一个检测器**同时输出人员、PPE、机械类别即可，不必拆多分支
3. **两组实验**：

| 实验 | 训练数据 | 用途 |
|---|---|---|
| **E1** | 只用真实数据，**关闭**所有内置增广 | 纯基线 |
| **E2** | 真实数据 + 传统增广（mosaic / 翻转 / HSV 等 YOLO 默认增广） | **阶段二要超越的对象** |

> ⚠️ **Ultralytics 默认开启 mosaic、翻转、HSV 抖动等增广**。E1 必须显式把 `mosaic`、`fliplr`、`hsv_h/s/v`、`scale`、`translate` 等参数设为 0，否则 E1 和 E2 实际没有区别。

4. **逐类别错误分析**：在 TelecomEval 上输出每个类别的 AP 与混淆矩阵，列出**最差的 3–5 个类别**——这份清单就是阶段二的生成目标
5. **固定配置**：模型尺寸、输入尺寸、epoch、随机种子、数据划分全部写入 `configs/baseline.yaml` 并提交。**阶段二的 E3 必须用同一份配置，只改训练数据**

#### ④ 判断 · 规则出风险等级

> **输入**：检测框（类别 + 坐标 + 置信度）｜ **输出**：每张图的风险等级（低 / 中 / 高）+ 触发的规则列表
> **时间**：W5–W7（与 ③ 并行）｜ **负责**：成员 E ｜ **决策门**：TGB

只做原三级融合的**前两级**（实体关系 + 规则），不做可学习层：

```
规则示例（基于检测框几何关系，纯 Python 即可）
R1  person 且 无 helmet                    → 中风险
R2  person 且 无 vest                      → 低风险
R3  person 处于塔上/高处 且 无 harness      → 高风险
R4  person 与 machinery 距离 < 安全半径     → 高风险（用人框高度估算实际尺度）
...
整图风险等级 = 所有触发规则中的最高等级
```

- 规则从 Taxonomy 中直接取，**每条标注法规出处**（OSHA / GB 等），5–10 条足够
- "无安全帽"优先直接用数据集自带的 `NO-Hardhat` 类，比"找不到帽子框"的推断更可靠
- **为什么能并行**：规则只依赖检测结果的**格式**（类别名 + 框），③ 的模型没训完之前，可以先用手写的假检测结果开发和测试

#### ⑤ Demo v1 · Baseline 产品

> **输入**：③ 的权重 + ④ 的规则 ｜ **输出**：可运行的小型 Demo
> **时间**：W6–W7 ｜ **负责**：成员 E ｜ **决策门**：TGB

- **工具**：Gradio（几十行代码即可出界面）或 Streamlit
- **功能**：上传图片 → 叠加检测框 → 风险等级卡 → 触发的规则列表（含条款出处）
- **不做**：用户系统、数据库、视频流、部署加速——这些都不是评分点
- **结构**：内部拆成 `detect(image)` → `judge(boxes)` → `render(result)` 三个函数，阶段二只换 `detect` 的权重

#### ⑥ 造料 · 生成式增广 ★ 核心创新 ★

> **输入**：TelecomSeed + baseline 弱类别清单 ｜ **输出**：TelecomSynth（带标注的合成图像）
> **时间**：W8–W10 ｜ **负责**：成员 B（主）+ 成员 A（副）｜ **决策门**：TG2

**和原计划的区别**：不再盲目覆盖所有类别，而是**按 ③ 的错误分析定目标**，只针对最差的几个类别造数据。

四条路线**按风险从低到高推进**：

| 顺序 | 路线 | 做法 | 标注从哪来 |
|---|---|---|---|
| 1 | **Inpainting 编辑** | 在真实图上把安全帽"擦掉" | 原标注直接继承，只改标签 |
| 2 | **背景替换** | 换成雨天、夜间、雾天 | 标注完全不变 |
| 3 | **T2I 新场景** | 文字描述生成罕见危险场景 | Grounding DINO 自动标注 + 核对 |
| 4 | **ControlNet 布局** | 先画语义布局图，再生成图像 | 布局图本身就是标注 |

前两条基于真实图像编辑，域间隙最小，几乎不会失败；后两条视时间推进。生成后过**四道质量闸门**（语义 / 分布 / 标注 / 人工），详细设计见 [文档 03](03-生成式数据增广Pipeline设计-CN.md)。

> 💡 **成员 B 在阶段一不要闲着**：W4–W7 提前搭好生成环境（SDXL + LoRA + Inpainting 试跑），否则 W8 才开工会把阶段二压得很紧。

#### ⑦ 对比 · 同配置再训练 ★ 项目成败点 ★

> **输入**：TelecomSeed + TelecomSynth ｜ **输出**：E3 结果 + 与 E1/E2 的对比表 ｜ **Demo v2**
> **时间**：W11–W12 ｜ **负责**：成员 C + 成员 D ｜ **决策门**：TG3

| 实验 | 训练数据 | 用途 |
|---|---|---|
| E1 | 只用真实数据（阶段一已完成） | 基线 |
| E2 | + 传统增广（阶段一已完成） | 排除"随便加数据就涨"的质疑 |
| **E3** | **+ 生成式增广** | **证明本项目的方法有效** |

- 用 `configs/baseline.yaml` **同一份配置**，只改训练数据，在**同一份** TelecomEval 上评估
- 除了整体 mAP，重点看**目标弱类别**的提升——这是阶段二最有说服力的数字
- 通过后把新权重换进 Demo，即得到 **Demo v2**

#### ⑧ 升级与交付

> **输入**：全部模型与实验结果 ｜ **输出**：完整实验 + Demo v2 + EE6008 报告与答辩
> **时间**：W13–W16 ｜ **负责**：成员 E（系统）+ 全员（实验与报告）｜ **决策门**：TG4、TG5

| | 内容 | 分量 |
|---|---|---|
| **融合升级** | 在阶段一的规则之上加第 3 级可学习融合（可选，TG4 不达标就保留纯规则） | 次核心创新 |
| **完整实验** | E4–E9：域间隙、配比曲线、长尾类别、**鲁棒性（E7）**、融合消融、跨站点泛化 | ⭐ **真正的学术交付物** |
| **Demo v2 + 报告** | 换上增广后的权重；报告写 baseline → 增广的完整对比 | 答辩用 |

**为什么实验比 Demo 重要**：项目简介要求 `develop and evaluate`，且明确写了 `high effectiveness and robustness`。Effectiveness 靠 E3 证明，Robustness 靠 E7 证明。**很多学生项目会把时间全花在界面上，把 E7 漏掉，这是失分点。**

### 2.3 两阶段衔接的三条硬约束

两阶段能成立的前提是：**阶段二的 E3 和阶段一的 E1/E2 可以公平对比**。为此以下三样东西在阶段一定下后**不再改动**：

| 固定什么 | 为什么 | 怎么做 |
|---|---|---|
| **TelecomEval 测试集** | 测试集变了，E3 和 E1/E2 的数字就不可比 | 划出后立即冻结；记录文件列表的哈希值；不参与训练、LoRA、生成条件构建 |
| **baseline 训练配置** | 配置变了，提升可能来自调参而不是增广 | `configs/baseline.yaml` 提交后只读；E3 只改训练数据 |
| **Demo 的三段接口** | 接口变了，阶段二要重写 Demo | `detect` → `judge` → `render` 解耦，阶段二只换权重 |

**唯一可以并行提前做的**是 ⑧ 需要的专家风险标注（200 张打风险等级，作为 TG4 的标准答案），它不在关键路径上，但常被拖到最后导致 TG4 无法评估。建议 W10 就开始约人。

### 2.4 最容易被误解的地方

| 误解 | 实际情况 |
|---|---|
| "Baseline Demo 做出来项目就完成了" | Baseline 只是起点。**生成式增广是立项理由**，没有阶段二的 E3 对比，项目就只是"用公开数据训了个检测器" |
| "先不做增广 = 放弃增广" | 不是放弃，是推迟并变得更有针对性。baseline 的错误分析正是阶段二的输入 |
| "生成数据就是把图片翻转、裁剪一下" | 那是**传统增广**（对应 E2）。本项目做的是用扩散模型**造出原本不存在的场景**，两者在 E2/E3 里是对照关系，必须分清 |
| "合成数据越多越好" | ❌ 未经筛选的合成数据**会降低**性能（负迁移）。这也是四道质量闸门存在的原因，宁可丢掉一半也不能污染训练集 |

## 3. 三个视野

| | H1 · Baseline Demo<br/>W1–W7 | H2 · 生成增广完整框架<br/>W8–W16 | H3 · 延伸<br/>项目后 |
|---|---|---|---|
| **目标** | "能跑、能演示" | "能证明、能评估" | "能发表 / 能落地" |
| **数据** | T1+T2+T3 公开数据（已整编） | + TelecomSynth 合成数据 | + 数据集公开发布 |
| **生成** | 不做 | Inpainting + 背景替换 → T2I / ControlNet · 闸门 G1–G4 | + 视频生成 |
| **感知** | YOLOv11 单检测器 · Workers + Machinery | 同配置再训练；视进度加 Terrain / Materials / 骨架动作 | + 双流融合 |
| **融合** | 5–10 条硬规则直判 | + 第 3 级可学习融合（可选） | + D-S 证据理论对照 |
| **系统** | Gradio Demo v1 | Demo v2（换权重） | + 边缘部署 |

> ⚠️ **H1 的 baseline 数字就是 H2 的对照基准**。H1 结束时必须把 E1/E2 结果、逐类 AP、配置文件、TelecomEval 版本一并归档。

## 6. 关键路径与风险集中点

**阶段一关键路径**：`Taxonomy ✅ → 数据整编 ✅ → 类别映射表 → baseline 训练 → Demo v1`
**阶段二关键路径**：`弱类别清单 → 生成（Inpainting 优先）→ 质量闸门 → 同配置再训练 → E3`

四个容易被低估的点：

1. **类别映射表**：各公开数据集标签命名不统一，合并前必须对齐到 Taxonomy。这是阶段一最早、也最容易被忽略的瓶颈，建议 W4 第一件事就做。
2. **baseline 的"固定"**：配置、数据划分、随机种子、TelecomEval 版本一旦提交就不再改。事后再想"调一下 baseline"，阶段二的对比就说不清了。
3. **阶段二的启动**：Demo v1 做出来后团队容易松劲。TGB 会议上就要确定弱类别清单和 ⑥ 的开工日期，成员 B 在阶段一就要把生成环境准备好。
4. **专家风险标注（TG4 的标准答案）**：不在关键路径上，但常被拖到最后导致 TG4 无法评估。建议 W10 就开始约人。

**技术成熟度与人力分配**：

| 把握度 | 技术 | 分配建议 |
|---|---|---|
| 🟢 **成熟** | YOLOv11 检测、Gradio、SDXL+LoRA、SD Inpainting、SAM 2、Grounding DINO | 交给经验较少的成员，直接用现成方案 |
| 🟡 **中等** | 类别映射与数据集合并、ControlNet-Seg 布局控制、ST-GCN++ 骨架动作、闸门阈值标定、规则谓词库 | 需预留调试时间；ControlNet 的布局图程序化生成工作量常被低估 |
| 🔴 **新颖** | 三级信息融合（可学习层）、地形语义分割、材料堆放判定 | **最强人力放这里**；后两项无公开数据、类别定义主观，阶段一不做 |
