## 1. 路线图总原则

### 1.1 三条设计准则

| # | 准则 | 含义 |
|---|------|------|
| 1 | **每层都有可用的最简版本** | 任何技术层的第一个版本必须能跑通端到端，哪怕很粗糙。先有闭环，再谈精度 |
| 2 | **每个决策门都有退路** | 没有备选方案的技术不允许进入关键路径。所有 TG 门都定义了降级路径 |
| 3 | **创新集中，工程保守** | 创新预算全部押在生成式增广（L2）与信息融合（L4）；感知层（L3）与系统层（L5）一律选成熟方案，不做技术冒险 |

### 1.2 三个视野（Three Horizons）

```
H1  MVP 闭环           W1–W9    "能跑通"
    └─ 单维度（Workers）+ 基础生成 + 检测输出
       目标：证明生成式增广有效（E3 实验为准）

H2  完整框架           W10–W16  "能评估"
    └─ 四维感知 + 三级融合 + 系统集成 + 全实验
       目标：交付可答辩的完整 TelecomSafe

H3  延伸方向           项目后    "能发表 / 能落地"
    └─ 视频行为、UAV 视角、边缘部署、数据集开源、期刊投稿
       目标：超出课程要求的学术与工程价值
```

> ⚠️ **H1 不达标就不要进 H2**。如果 W9 时 E3 实验证明生成数据没有带来提升，继续堆四维感知只会放大问题。宁可在 H1 多花两周。

## 3. 技术决策门（Technology Gates）

决策门是路线图的核心机制：**到达指定时间点后，用客观指标判断继续、调整还是降级**。每个门都必须在团队会议上正式过一次，结论写入会议纪要。

### TG1 ｜ W3 末 — 数据基础门

| 项 | 内容 |
|----|------|
| **判据** | TelecomSeed（来自 T2/T3 公开来源）≥ 200 张已标注；TelecomEval 测试集已划出并冻结 ≥ 150 张；Risk Taxonomy v1.0 定稿 |
| ✅ 通过 | 按计划进入生成 pipeline 开发 |
| ⚠️ 部分达标（100–200 张） | 缩减 Risk Taxonomy 至 4 大类 × 12 细类；生成阶段更依赖 ControlNet 与 Inpainting 而非 T2I；测试集下限降至 100 张并在报告中说明 |
| ❌ 未达标（< 100 张） | **降级路径 D1**：放弃"电信专用"定位，改为"高处作业 + 塔架类施工"泛化场景。此时测试集改用 T1/T2 中筛选出的高处作业子集（如 safety harness 数据集），并在报告中明确重新界定范围 |

### TG2 ｜ W6 末 — 生成质量门 ★最关键★

| 项 | 内容 |
|----|------|
| **判据** | FID(合成, 真实) < 50；人工真实性评分 ≥ 3.0/5；闸门后保留率 ≥ 40% |
| ✅ 通过 | 批量生成 3000 张，进入感知模型训练 |
| ⚠️ 部分达标（FID 50–70） | 提高 Inpainting 路线占比至 50%（域间隙最小），减少纯 T2I |
| ❌ 未达标（FID > 70 或评分 < 2.5） | **降级路径 D2**：放弃 T2I 全新场景生成，只保留 Inpainting + 背景替换两条"基于真实图像编辑"的路线。这两条路线域间隙天然最小，几乎不会失败 |

### TG3 ｜ W9 末 — 增广有效性门 ★项目成败点★

| 项 | 内容 |
|----|------|
| **判据** | E3（生成增广）相对 E2（传统增广）mAP 提升 ≥ 2.0 |
| ✅ 通过 | 进入 H2，展开四维感知与融合 |
| ⚠️ 提升 0–2.0 | 诊断顺序：① 检查标签噪声（一致性核对是否生效）② 调低合成配比至 25% ③ 改用类别自适应配比，只对长尾类补数据 |
| ❌ 无提升或下降 | **降级路径 D3**：把研究问题从"生成数据提升整体性能"改为**"生成数据提升长尾类别性能"**——只报告稀有类 AP，这个更窄的结论通常仍然成立，且学术上依然有价值。诚实说明整体未提升 |

> **关于 D3 的说明**：这不是失败，而是把结论限定在真实成立的范围内。Kim & Yi (2024) 纯生成数据 mAP 仅约 64%，说明域间隙客观存在；报告一个受限但真实的结论，比强行宣称全面提升要可信得多。

### TG4 ｜ W11 末 — 融合可行性门

| 项 | 内容 |
|----|------|
| **判据** | 风险等级判定 Accuracy ≥ 0.70（对照专家标注 200 张） |
| ✅ 通过 | 保留三级融合，进入系统集成 |
| ⚠️ 0.55–0.70 | 去掉第 3 级可学习融合，只保留 L1 实体图 + L2 规则层（纯规则通常更稳且完全可解释） |
| ❌ < 0.55 | **降级路径 D4**：检查专家标注一致性（Kappa < 0.5 说明标注本身不可靠，问题不在模型）。若标注可靠则简化为"最高单项风险即为整体风险"的保守规则 |

### TG5 ｜ W13 末 — 系统集成门

| 项 | 内容 |
|----|------|
| **判据** | 端到端 pipeline 可运行；单图推理 < 3 秒；Demo 界面可演示 |
| ✅ 通过 | 进入全面评估 |
| ❌ 未达标 | **降级路径 D5**：放弃 Web 界面，改为脚本 + 可视化图片输出 + 录屏演示。答辩效果略降但不影响学术结论 |

## 4. 技术依赖关系与关键路径

```
Risk Taxonomy ──┬──> 标注规范 ──> 种子数据集 ──┬──> LoRA 微调 ──> 生成引擎 ──┐
   [TG1]        │                              │      [TG2]                 │
                │                              │                            ▼
                └──> 规格库(Stage 0) ──────────┘                    合成数据集
                                                                          │
                                                                          ▼
公开数据集 ────────> 预训练/迁移 ────────> 感知模型基线(E1) ──> 混合训练(E3) [TG3]
                                                │                        │
                                                ▼                        ▼
                                          四分支感知输出 ──────> 实体图构建
                                                                          │
安全规范文本 ──────> 规则谓词库 ────────────────────────────> 规则层 [TG4]
                                                                          │
专家风险标注 ──────────────────────────────────────────────> 可学习融合
                                                                          │
                                                                          ▼
                                                                  系统集成 [TG5]
```

### 关键路径（Critical Path）

**Risk Taxonomy → 标注规范 → 种子数据 → LoRA → 生成引擎 → 合成数据 → E3 实验**

这条链上任何一环延期，整个项目直接顺延。三点提示：

1. **Risk Taxonomy 是关键路径的起点，也是最容易被低估的一环。** 它不是"列个类别表"，而是要定义每个风险的**可判定标准**（什么叫"堆放不当"？高宽比超过多少？），否则标注、生成、评估三方会各说各话。
2. **T3 开放许可图像的检索与筛选是唯一无法靠算力加速的环节**（现场采集已取消，但人工检索筛选仍是体力活）。建议 W1 就并行启动，不要等 Taxonomy 完全定稿。同时**逐张记录许可与署名**，事后补记几乎不可能。
3. **专家风险标注（融合层 GT）可以并行提前做**，不在关键路径上，但常被拖到最后导致 TG4 无法评估。建议 W8 就开始约人。

## 5. 技术成熟度评估

用类 TRL（Technology Readiness Level）的方式标注每项技术在本项目中的把握程度，指导风险分配。

| 技术 | 成熟度 | 风险 | 说明 |
|------|--------|------|------|
| YOLOv11 目标检测 | 🟢 成熟 | 低 | 工业级方案，文档齐全，几乎不会失败 |
| SDXL + LoRA 微调 | 🟢 成熟 | 低 | 社区方案极多，教程完备 |
| SD Inpainting 编辑 | 🟢 成熟 | 低 | 标注可继承，最稳的生成路线 |
| SAM 2 分割 | 🟢 成熟 | 低 | 开箱即用 |
| Grounding DINO 预标注 | 🟢 成熟 | 低 | 显著提效，无技术风险 |
| ControlNet-Seg 布局控制 | 🟡 中等 | 中 | 需要程序化生成布局图，工程量被普遍低估 |
| ST-GCN++ 骨架动作 | 🟡 中等 | 中 | **依赖视频数据**，若无数据则整条线不可行（见 D6） |
| 质量闸门阈值标定 | 🟡 中等 | 中 | 无现成标准，需自行实验确定，占用 W6 大量时间 |
| 三级信息融合 | 🔴 新颖 | 高 | 本项目原创设计，无成熟先例，需预留调试时间 |
| 规则谓词库构建 | 🟡 中等 | 中 | 技术不难，但需要查阅法规、与专家确认，耗时长 |
| 地形语义分割 | 🔴 新颖 | 高 | **无公开数据**，类别定义主观，最可能被降级的一环 |
| 材料堆放状态判定 | 🔴 新颖 | 高 | 同上，"不当"缺乏客观定义 |

**风险分配结论**：把团队最强的人力放在 🔴 项（融合、地形、材料），🟢 项可以交给经验较少的成员或直接用现成方案。

## 6. 降级路径总表

所有降级路径集中在此，便于团队在决策门会议上快速查阅。

| ID | 触发条件 | 降级动作 | 对成果的影响 |
|----|---------|---------|------------|
| **D1** | 电信真实数据 < 150 张 | 定位改为"高处作业/塔架类施工"泛化场景 | 削弱行业专用性（G1 空白），但不影响生成式增广的核心贡献 |
| **D2** | 生成质量 FID > 70 | 只保留 Inpainting + 背景替换路线 | 合成数据多样性下降，但域间隙更小，E3 反而可能更好 |
| **D3** | E3 无提升 | 结论收窄为"提升长尾类别性能" | 论文卖点变窄但依然成立，需诚实说明 |
| **D4** | 融合 Accuracy < 0.55 | 去掉可学习层，纯规则融合 | 失去 L4 的学习性创新，但可解释性反而更强 |
| **D5** | 系统集成失败 | 脚本 + 录屏演示替代 Web 界面 | 仅影响答辩观感，不影响学术结论 |
| **D6** | 无视频数据 | 行为识别改为**单帧姿态 + 规则判定**（如手臂角度判断攀爬） | 无法做时序动作，但 PPE + 姿态仍能覆盖多数不安全行为 |
| **D7** | 算力不足（< 16GB 显存） | SD 1.5 替代 SDXL；YOLOv11-s 替代 -m；8bit 量化 | 精度略降，全流程仍可跑通 |
| **D8** | 进度整体落后 2 周以上 | 砍掉 Terrain + Materials 两个维度，只做 Workers + Machinery | 从"四维"变"两维"，需在报告中重新界定范围 |

> **D8 是最后的保险。** 文档 01 §五 R7 已经建议一开始就主攻两个维度；如果按那个建议执行，D8 实际上就不需要了。

## 10. 路线图检查清单

每次决策门会议前，团队按此清单自查：

```
□ 上一阶段的判据数据是否已实测（不是估计）？
□ 决策门的三种结论（通过/部分/降级）分别对应什么动作，团队是否已达成一致？
□ 若触发降级，对应的 D 路径是否已评估过工作量？
□ 关键路径上是否有任务延期？延期多久？
□ 是否有新出现的技术风险需要加入 §8？
□ 会议结论是否已写入纪要并同步到仓库？
```

## 11. 一页速览
