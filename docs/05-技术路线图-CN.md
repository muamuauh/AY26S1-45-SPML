## 2. 流程详解与总览

### 2.1 一句话总览

常被问到：**这个项目的主线是不是「收集数据 → 生成更多数据 → 训练 → 前端展示」？**

大方向对，但**中间漏了一步，首尾两端也需要修正**。完整主线是六步：

```mermaid
flowchart LR
    classDef s fill:#e3f2fd,stroke:#1565c0,stroke-width:1px,color:#0d1b2a
    classDef core fill:#ffe0b2,stroke:#e65100,stroke-width:2px,color:#3e2723
    classDef out fill:#c8e6c9,stroke:#2e7d32,stroke-width:1px,color:#1b3a1e

    S1["<b>① 定标准</b><br/>Risk Taxonomy<br/><i>W1</i>"]:::s
    S2["<b>② 备料</b><br/>整编公开数据<br/><i>W2–W3</i>"]:::s
    S3["<b>③ 造料</b> ★<br/>生成式增广<br/><i>W4–W6</i>"]:::core
    S4["<b>④ 学习</b><br/>训练感知模型<br/><i>W7–W9</i>"]:::s
    S5["<b>⑤ 判断</b> ★<br/>融合出风险分<br/><i>W10–W11</i>"]:::core
    S6["<b>⑥ 交付</b><br/>Demo + 实验验证<br/><i>W12–W16</i>"]:::out

    S1 --> S2 --> S3 --> S4 --> S5 --> S6
```

**与常见理解的对照**：

| 常见理解 | 实际流程 | 差在哪 |
|---|---|---|
| 收集数据 | ① 定标准 → ② **整编**公开数据 | 前面要先定义"什么算风险"；而且**不做现场采集**，是从公开来源筛选 |
| 生成更多数据 | ③ 生成式增广 | ✅ 一致，这是项目第一个核心创新 |
| 训练 | ④ 训练感知模型 | ✅ 一致 |
| —— | ⑤ **信息融合出风险分** | ⚠️ **这一步被漏掉了**，而它是第二个核心创新 |
| 前端展示 | ⑥ Demo **+ 实验验证** | Demo 是给答辩看的；**E1–E9 实验数据才是真正的学术交付物** |

> 💡 **两个最重要的修正**
> 1. **④ 和 ⑥ 之间必须有 ⑤**。感知模型输出的是"这里有个没戴安全帽的人""那里有台挖掘机"，这是**一堆孤立的检测框**。而项目简介要求的是 `accurately appraise the potential risks`——要回答"这个作业面整体有多危险"。把前者变成后者，就是第 ⑤ 步做的事。
> 2. **⑥ 的重点不是前端**。Web Demo 只占很小的分量，真正的交付物是 E1–E9 实验（尤其 E3：证明生成的数据确实提升了性能）。没有实验数据，这个项目就只是"做了个软件"，不是研究。

### 2.2 六个步骤逐个说明

#### ① 定标准 · Risk Taxonomy

> **输入**：项目简介的四个风险维度 ｜ **输出**：可判定的风险分类体系（4 大类 × 20–30 细类）
> **时间**：W1 ｜ **负责**：成员 A ｜ **决策门**：TG1

把"地形不平整""材料堆放不当"这类模糊描述，翻译成**机器和人都能一致判定的标准**。例如"堆放不当"要写成"堆高/底宽比 > 1.5，或越出划定区域，或阻塞通道"。

**为什么不能省**：标注的人、写生成提示词的人、做评估的人，三方必须对同一个词理解一致。定义含糊的后果不是"标注慢一点"，而是**三方各做各的，最后数据对不上、实验结论无效**。这也是它排在最前面、且是关键路径起点的原因。

#### ② 备料 · 整编公开数据

> **输入**：网上公开数据源 ｜ **输出**：TelecomSeed（200–500 张）+ 🔒 TelecomEval（150–300 张，冻结）
> **时间**：W2–W3 ｜ **负责**：成员 A（全员协助检索）｜ **决策门**：TG1

**不是去工地拍照**，而是三层公开来源的筛选整编：

- **T1 学术数据集**（SODA / CHV / SHEL5K 等，2 万张以上）—— 通用工地，作迁移基座
- **T2 社区数据集**（Roboflow Universe 的电信塔集与 safety harness 集、Kaggle 施工安全集）—— 有电信塔和安全带的专项数据，且自带 NO-Hardhat 负类
- **T3 开放许可图像**（Wikimedia Commons / Openverse）—— 人工检索筛选，**这是电信专用性的唯一来源**

**为什么不能省**：生成模型需要真实图像做微调种子（否则生成不出电信场景的样子），实验需要真实图像做测试标尺。⚠️ 检索时**必须逐张记录来源与许可署名**，CC BY / CC BY-SA 的硬性要求，事后补记几乎不可能。

#### ③ 造料 · 生成式增广 ★ 第一个核心创新 ★

> **输入**：TelecomSeed + 风险场景规格库 ｜ **输出**：TelecomSynth（3,000–10,000 张带标注合成图像）
> **时间**：W4–W6 ｜ **负责**：成员 B（主）+ 成员 A（副）｜ **决策门**：TG2

用 SDXL + LoRA 学会电信施工的样子，再用四条路线批量造数据：

| 路线 | 做法 | 标注从哪来 |
|---|---|---|
| **Inpainting 编辑** | 在真实图上把安全帽"擦掉" | 人框标注直接继承，只改标签 |
| **ControlNet 布局** | 先画语义布局图，再生成图像 | 布局图本身就是分割标注 |
| **T2I 新场景** | 文字描述生成罕见危险场景 | 需 Grounding DINO 自动标注 + 核对 |
| **背景替换** | 换成雨天、夜间、雾天 | 标注完全不变 |

生成后过**四道质量闸门**（语义一致 / 分布一致 / 标注可靠 / 人工抽检），预期只留下 50–65%。

**为什么不能省**：这是整个项目的立项理由。真实图像只有两三百张，训不出可用模型；而最危险的场景（未系安全带在塔上探身）在真实数据里根本拍不到，也不可能去拍。**⚠️ 关键点是"生成即标注"**——如果合成图还要人工标注，就等于没解决问题。上表四条路线里有三条的标注是白来的。

#### ④ 学习 · 训练感知模型

> **输入**：TelecomSeed + TelecomSynth 混合 ｜ **输出**：四分支感知模型 + E1/E2/E3 实验结果
> **时间**：W7–W9 ｜ **负责**：成员 C（人员）+ 成员 D（场景）｜ **决策门**：TG3 ← **项目成败点**

四个并行分支，各管一个维度：Workers（人+PPE+姿态）、Machinery（机械+状态）、Terrain（地面分割）、Materials（堆放判定）。

同时跑三组对比实验，这是**全项目最重要的一组数字**：

| 实验 | 训练数据 | 用途 |
|---|---|---|
| E1 | 只用真实数据 | 基线 |
| E2 | + 传统增广（翻转/裁剪） | 排除"随便加数据就涨"的质疑 |
| **E3** | **+ 生成式增广** | **证明本项目的方法有效** |

**为什么不能省**：E3 减 E2 的差值，就是这个项目的价值证明。如果提升不到 2 个 mAP，就要走降级路径 D3（把结论收窄为"提升长尾稀有类别"）而不是硬推。

#### ⑤ 判断 · 信息融合 ★ 第二个核心创新，也是最容易被漏的一步 ★

> **输入**：四分支的检测/分割/属性输出 ｜ **输出**：场地级风险评分 + 可解释的触发原因
> **时间**：W10–W11 ｜ **负责**：成员 E ｜ **决策门**：TG4

把一堆孤立检测框变成一个可解释的风险判断，分三级：

```
第 1 级  实体图     把人、机械、材料、地形关联起来
                    例：worker_1 --[距离 1.2m]--> excavator_1
                        worker_2 --[站立于]--> 不平整地面_3

第 2 级  规则层     把安全规范写成可判定的条件
                    高处作业 且 无安全带        → 严重违规
                    人机距离 < 安全半径          → 高风险
                    坑槽边 1m 内有人 且 无护栏   → 高风险

第 3 级  可学习融合  用 GNN 学习规则之间的权重与交互
                    输出 0–1 的风险分 + 每个风险源的贡献度
```

**为什么不能省**：这是"检测"和"风险评估"的分界线。只做到 ④，交付的是一个检测器；做到 ⑤，交付的才是项目简介要求的**风险评估框架**。而且规则层直接对齐 OSHA / GB 26859 等真实规范，让评分**可追溯到具体条款**——安全领域的决策必须能解释，纯黑箱模型行业不会接受，这也是打动评审的地方。

#### ⑥ 交付 · 系统展示 + 实验验证

> **输入**：全部模型与实验结果 ｜ **输出**：Web Demo + E1–E9 完整实验 + EE6008 报告
> **时间**：W12–W16 ｜ **负责**：成员 E（系统）+ 全员（实验与报告）｜ **决策门**：TG5

两块内容，**权重不一样**：

| | 内容 | 分量 |
|---|---|---|
| **系统 Demo** | 上传图片 → 四维检测叠加 → 风险评分卡 → 触发的规则列表 | 答辩演示用，观感重要但学术分量小 |
| **实验验证** | E1–E9 全套：增广有效性、域间隙、配比曲线、长尾类别、**鲁棒性**、融合消融、跨站点泛化 | ⭐ **真正的学术交付物** |

**为什么实验比 Demo 重要**：项目简介要求 `develop and evaluate`，且明确写了 `high effectiveness and robustness`。Effectiveness 靠 E3 证明，Robustness 靠 E7 证明（低光/雨雾/模糊/小目标下性能衰减多少）。**很多学生项目会把时间全花在界面上，把 E7 漏掉，这是失分点。**

### 2.3 为什么是这个顺序

每一步都**卡着下一步的脖子**，顺序不能调：

```
① 不定义清楚风险 → ② 不知道该筛什么图、③ 不知道该生成什么场景
② 没有真实种子   → ③ 生成模型学不会电信场景的样子
③ 没有合成数据   → ④ 只有两三百张真实图，模型训不起来
④ 没有感知输出   → ⑤ 融合层没有输入可融
⑤ 没有风险评分   → ⑥ 只能展示检测框，展示不了"风险评估"
```

这条链就是**关键路径**：任何一环延期，整个项目顺延。所以文档 [01 §4](01-技术方案与里程碑-CN.md) 把 ①② 放在最前两周，且建议 ② 在 W1 就并行启动，不等 ① 完全定稿。

**唯一可以并行提前做的**是第 ⑤ 步需要的专家风险标注（200 张打风险等级），它不在关键路径上，但常被拖到最后导致 TG4 无法评估。建议 W8 就开始约人。

### 2.4 三个最容易被误解的地方

| 误解 | 实际情况 |
|---|---|
| "生成数据就是把图片翻转、裁剪一下" | 那是**传统增广**（对应 E2）。本项目做的是用扩散模型**造出原本不存在的场景**，两者在 E2/E3 里是对照关系，必须分清 |
| "有了 Demo 界面项目就完成了" | Demo 只是 ⑥ 的一半。没有 E1–E9 实验数据，等于交了个软件作业而不是研究项目 |
| "合成数据越多越好" | ❌ 未经筛选的合成数据**会降低**性能（负迁移）。这也是四道质量闸门存在的原因，宁可丢掉一半也不能污染训练集。消融实验 A4 专门验证这一点，通常能得到"无闸门时性能下降、加闸门后由降转升"的漂亮反转 |

## 3. 三个视野

| | H1 · MVP 闭环<br/>W1–W9 | H2 · 完整框架<br/>W10–W16 | H3 · 延伸<br/>项目后 |
|---|---|---|---|
| **目标** | "能跑通" | "能评估" | "能发表 / 能落地" |
| **数据** | T1+T2 迁移 · T3 整编 200–500 张 | + 地形/材料子集 | + 数据集公开发布 |
| **生成** | SDXL+LoRA · T2I+Inpainting · 闸门 G1+G3 | + ControlNet 全套 · 闸门 G1–G4 | + 视频生成 |
| **感知** | 单分支 Workers | 四分支并行 + 骨架动作 | + 双流融合 |
| **融合** | 5 条硬规则直判 | 三级分层融合 + GNN | + D-S 证据理论对照 |
| **系统** | CLI 脚本 | FastAPI + Web Demo | + 边缘部署 |

> ⚠️ **H1 不达标就不要进 H2**。若 W9 的 E3 实验证明生成数据没有提升，继续堆四维感知只会放大问题。宁可在 H1 多花两周。

**每个门都有退路，所以没有单点失败。** 判据与动作：

| 门 | 时点 | 判据 | 未达标动作 |
|---|---|---|---|
| **TG1** 数据基础 | W3 末 | TelecomSeed ≥200 张已标注；TelecomEval ≥150 张已冻结 | <100 张 → **D1**：放弃"电信专用"定位，改为高处作业/塔架类泛化场景，测试集改用 T1/T2 的高处作业子集 |
| **TG2** 生成质量 | W6 末 | FID(合成,真实) < 50；人工真实性 ≥3.0/5；闸门保留率 ≥40% | FID>70 → **D2**：只保留 Inpainting 与背景替换两条基于真实图像编辑的路线（域间隙天然最小，几乎不会失败） |
| **TG3** 增广有效性 | W9 末 | E3 相对 E2 的 mAP 提升 ≥2.0 | 无提升 → **D3**：先查标签噪声与配比；仍无效则把结论收窄为"提升长尾稀有类别性能"，诚实说明整体未提升 |
| **TG4** 融合可行性 | W11 末 | 风险等级 Accuracy ≥0.70（对照 200 张专家标注） | <0.55 → **D4**：先查标注一致性（Kappa<0.5 说明问题在标注不在模型）；否则去掉第 3 级可学习融合，纯规则更稳且完全可解释 |
| **TG5** 系统集成 | W13 末 | 端到端可运行；单图推理 <3 秒 | 未达标 → **D5**：脚本 + 可视化输出 + 录屏演示替代 Web 界面（仅影响答辩观感，不影响学术结论） |

| ID | 触发 | 动作 |
|---|---|---|
| **D6** | 无视频数据 | 行为识别改为单帧姿态 + 规则判定（如手臂角度判断攀爬） |

## 6. 关键路径与风险集中点

**关键路径**：`Risk Taxonomy → 标注规范 → 公开数据整编 → LoRA → 生成引擎 → 合成数据 → E3 实验`

三个容易被低估的点：

1. **Risk Taxonomy 不是"列个类别表"**，而是要定义每个风险的**可判定标准**（什么叫"堆放不当"？高宽比超过多少？）。定义不清，标注、生成、评估三方会各说各话。
2. **T3 开放许可图像的检索筛选是唯一无法靠算力加速的环节**，建议 W1 就并行启动。⚠️ **必须当场逐张记录来源 URL 与许可署名**，事后补记几乎不可能（CC BY / CC BY-SA 的硬性义务）。
3. **专家风险标注（TG4 的 GT）可以提前并行做**，不在关键路径上，但常被拖到最后导致 TG4 无法评估。建议 W8 就开始约人。

**技术成熟度与人力分配**：

| 把握度 | 技术 | 分配建议 |
|---|---|---|
| 🟢 **成熟** | YOLOv11 检测、SDXL+LoRA、SD Inpainting、SAM 2、Grounding DINO | 交给经验较少的成员，直接用现成方案 |
| 🟡 **中等** | ControlNet-Seg 布局控制、ST-GCN++ 骨架动作、闸门阈值标定、规则谓词库 | 需预留调试时间；ControlNet 的布局图程序化生成工作量常被低估 |
| 🔴 **新颖** | 三级信息融合、地形语义分割、材料堆放判定 | **最强人力放这里**；后两项无公开数据、类别定义主观，是 D8 首先砍掉的对象 |
