## Project Purpose or Justification（立项目的与依据）

> *模板要求：Describe the reason or justification the project is being undertaken.*

电信施工现场存在多类安全风险，包括地形不平整、机械操作不当、材料堆放不当、个人防护装备缺失以及工人不安全行为。传统的人工巡检方式耗时、主观且难以持续覆盖。

基于深度学习的计算机视觉为自动化安全监测提供了有效手段，但其在电信行业的应用受到一个关键瓶颈的制约：**行业专用标注图像既稀缺又缺乏多样性**。这一瓶颈有三重成因：

1. **数据分布差异**：现有公开施工数据集（SODA、MOCS、ACID 等）均来自房建与市政工地。电信场景——格构式铁塔、单管塔、基站机房、光缆沟槽、楼顶天线——在目标形态、拍摄视角、作业高度上与之存在系统性差异，通用模型直接迁移会显著衰减。

2. **长尾风险不可采集**：真正危险的场景（如工人未系安全带在塔上探身作业）在真实数据中极度稀少；即便遇到，出于伦理、法律与劳动关系原因也难以拍摄与公开。这构成数据获取的结构性死结。

3. **缺乏电信专用资源**：经系统检索 Google Scholar、IEEE Xplore 与 ACM Digital Library，**未发现任何公开的、面向电信施工安全的标注数据集或专用框架**。最接近的工作是通信塔的资产巡检（商业产品层面），而非施工过程安全。

> **数据来源约束**：经与导师沟通，本项目**不进行任何现场数据采集**（安全风险与成本过高），全部真实数据取自网上公开数据集与开放许可图像库。
> 这一约束**反而印证了上述第 2、3 条**：团队自身无法承担采集成本，必须依赖生成式方法，恰好亲身验证了「电信专用数据难以获取」这一立项前提。

本项目正是为填补这一空白而立项。TelecomSafe 引入**生成式人工智能**合成训练数据以突破数据稀缺，并结合深度学习图像处理与信息融合，从地形、机械、材料、人员四个维度对施工风险进行综合评估。项目同时具备**学术价值**（该研究方向的相关工作集中于 2024–2026 年，选题时效性强，且无一针对电信领域）与**工程价值**（可迁移至电信运营商与工程承包商的实际安全管理）。

## Project Description（项目描述）

> *模板要求：Provide a summary description of the project. This section may include information on project deliverables as well as the approach of the project.*

### 项目概述

TelecomSafe 是一个面向电信施工场景的多维度安全风险智能识别框架。其核心创新在于**以生成式数据增广解决行业数据稀缺问题**，并**以分层信息融合将单点检测转化为可解释的场地级风险评估**。

项目按导师建议**分两阶段**推进：**阶段一**只用已整编的公开数据，训练 baseline 感知模型、以安全规则判断风险等级，交出一个可运行的 Baseline Demo；**阶段二**再引入生成式数据增广，在同一测试集、同一训练配置下与 baseline 对比，证明增广带来的提升。

### 技术方案

系统采用五层架构：

| 层 | 名称 | 内容 |
|----|------|------|
| **L1** | 输入层 | 静态图片（阶段一范围）；视频、UAV 航拍、塔上记录仪（扩展项） |
| **L2** | **数据层 ★核心创新★** | 公开数据整编标注（T1 学术集 / T2 社区集 / T3 开放许可图像）+ 生成式增广 pipeline + 四道质量闸门。**不含任何现场采集** |
| **L3** | 感知层 | 阶段一：Workers（人员与 PPE）+ Machinery 单检测器；阶段二视进度加入 Terrain 分割与 Materials 状态判定 |
| **L4** | **融合决策层 ★次核心★** | 阶段一：安全规范规则直判风险等级；阶段二：实体图 → 规则层 → 可学习融合 → 风险评分 |
| **L5** | 应用层 | Demo（阶段一 v1 / 阶段二 v2）：检测可视化、风险评分卡、触发规则列表 |

### 核心方法：生成式数据增广（阶段二）

采用 SDXL + LoRA 领域适配，**按 baseline 逐类别错误分析得出的弱类别定向生成**。生成路线按风险从低到高推进：

- **Inpainting 局部编辑** —— 在真实图像上擦除安全帽等 PPE，边界框标注可直接继承（域间隙最小）
- **背景替换** —— 生成雨、雾、夜间等鲁棒性测试数据，标注不变
- **Text-to-Image** —— 生成真实世界完全缺失的稀有危险场景
- **ControlNet 布局控制** —— 语义布局图既是生成条件，也直接构成分割标注（标注零成本）

所有合成数据须通过四道质量闸门（G1 语义一致性 / G2 分布一致性 / G3 标注可靠性 / G4 人工抽检），预期保留率 50–65%。

### 数据来源（纯公开来源，零现场采集；T1–T3 已于线下整编完成）

| 层 | 来源 | 内容 | 规模 |
|----|------|------|------|
| **T1** | 学术公开数据集 | SODA、MOCS、ACID、CHV、SHEL5K、SHWD、Pictor-v3 | 20,000+ 张（迁移基座） |
| **T2** | 社区数据集平台 | Roboflow Universe（电信塔集、safety harness 系列）、Kaggle 施工安全集（含 NO-Hardhat 等负类） | 2,000–5,000 张 |
| **T3** | 开放许可图像库 | Wikimedia Commons、Openverse、Flickr CC —— 人工检索筛选，逐张记录来源与署名 | 200–500 张（电信专用性来源） |
| **T4** | 生成式合成 | 本项目核心产出 TelecomSynth | 3,000–10,000 张 |

> 🔒 **测试集纪律**：TelecomEval（150–300 张，取自 T2/T3 的真实图像）全程冻结，绝不参与 LoRA 微调与生成条件构建。这是全部实验结论成立的前提。
> ⚖️ **许可合规**：CC BY / CC BY-SA 要求署名，须随报告提交 `licence_manifest.csv`。

### 主要可交付成果

| 类别 | 交付物 |
|------|--------|
| **数据** | Risk Taxonomy（电信施工风险分类体系）、标注规范、**TelecomSeed**（公开来源真实种子集 200–500 张）、🔒 **TelecomEval**（隔离测试集 150–300 张）、**TelecomSynth**（合成数据集 ≥3000 张）、`licence_manifest.csv`（开放许可署名清单） |
| **模型** | baseline 感知模型、LoRA 领域适配模型、生成引擎、增广后的感知模型、信息融合模块 |
| **系统** | Baseline Demo v1（阶段一）与增广后的 Demo v2（阶段二）：上传图片 → 检测框 → 风险评分卡 → 触发规则 |
| **实验** | E1–E9 完整实验结果，核心为 E3（生成增广有效性验证）与 E7（鲁棒性） |
| **文档** | EE6008 项目报告、答辩演示、代码仓库（含复现脚本） |

### 项目方法与关键判据

项目采用**两阶段 + 决策门（Decision Gate）**机制管理技术风险：阶段一先交出 Baseline Demo，阶段二再做生成式增广并与 baseline 对比。在 W3、W7、W10、W12、W14、W15 六个节点用客观指标判断继续、调整或降级，每个门均预设了降级路径（详见文档 [05 §4](05-技术路线图-CN.md)）。

关键门：

| 门 | 时点 | 判据 |
|----|------|------|
| **TG1** 数据基础 | W3 末 | TelecomSeed ≥200 张；TelecomEval ≥150 张且冻结 —— ✅ 整编已于线下完成 |
| **TGB** Baseline | W7 末 | Demo v1 端到端可运行；E1/E2 在 TelecomEval 上的结果已记录；baseline 训练配置已固定 |
| **TG2** 生成质量 | W10 末 | FID(合成, 真实) < 50；人工真实性评分 ≥3.0/5 |
| **TG3** 增广有效性 | W12 末 | E3 相对 E2 的 mAP 提升 ≥2.0（整体或弱类别）—— **项目成败判定点** |

### 范围界定说明

四个风险维度全部做到高质量在一学期内难以实现。**已确定：阶段一只做 Workers 与 Machinery 两个维度；Terrain 与 Materials 在阶段二视进度再加**，并在最终报告中诚实说明范围界定。

无需走流程的情形：技术实现细节调整、超参数与模型配置变更、文档措辞修订、不影响交付时间的任务顺序调整。
