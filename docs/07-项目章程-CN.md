## 2. 立项依据 (Business Case)

### 2.1 问题陈述

电信施工现场的安全风险来自五个方面：**地形不平整、机械操作不当、材料堆放不当、个人防护装备缺失、以及工人不安全行为**。

基于深度学习的计算机视觉为识别这些风险提供了高效手段，但其性能受制于一个核心瓶颈：

> **电信行业专用的标注图像既稀缺又缺乏多样性**（limited availability and diversity of labelled, sector-specific images）。

经系统文献检索（Google Scholar / IEEE Xplore / ACM DL），**目前不存在任何公开的、面向电信施工场景的安全检测标注数据集**（详见 `04-文献综述-CN.md` §3.2）。现有工作中最接近的是通信塔的资产巡检应用，而非施工过程安全。

### 2.2 为什么现在做

1. **技术窗口成熟**：扩散模型与可控生成（ControlNet、Inpainting）在 2023–2024 年达到可用水平，使"生成即标注"成为可能
2. **研究空白明确**：施工安全领域的生成式增广工作集中在 2024–2026 年，方向新且尚无人做电信垂直领域
3. **数据获取的结构性困境**：真实违规照片涉及工人肖像权与劳动关系风险，难以合法采集与公开 —— 合成数据从根本上规避了这一问题

### 2.3 预期价值

| 类型 | 价值 |
|------|------|
| 学术 | 填补 5 项研究空白（G1–G5）；具备投稿 *Automation in Construction* 的潜力 |
| 数据 | 产出可公开的 TelecomSynth 合成数据集与 Risk Taxonomy，本身即可引用贡献 |
| 工程 | 提供可运行的电信施工安全评估原型系统 |
| 合规 | 合成数据方案规避真实工人隐私问题，具备实际推广条件 |

## 3. 项目目标与成功标准

### 3.1 总体目标

开发并评估一个面向电信施工安全的生成式图像学习框架，实现对**地形、机械、材料、人员**四个维度潜在风险的高有效性（high effectiveness）与高鲁棒性（robustness）识别。

### 3.2 具体目标与成功标准（SMART）

| # | 目标 | 成功标准（可测量） | 验证方式 | 优先级 |
|---|------|------------------|---------|--------|
| **O1** | 建立电信施工风险分类体系 | Risk Taxonomy 含 4 大类 × ≥20 细类，每类有可判定的量化标准 | 导师评审通过 | **必达** |
| **O2** | 构建生成式数据增广 pipeline | 产出 ≥3000 张通过质量闸门的合成图像；FID < 50；人工真实性 ≥3.0/5 | TG2 决策门 | **必达** |
| **O3** | 证明生成式增广有效 | E3 相对 E2（传统增广）mAP 提升 ≥2.0 | TG3 决策门 | **必达** |
| **O4** | 实现多维度感知 | ≥2 个维度达到可用精度（mAP@50 ≥0.70）；目标 4 个维度 | 实验报告 | **必达 2 个** |
| **O5** | 实现信息融合风险评估 | 风险等级判定 Accuracy ≥0.70（对照专家标注） | TG4 决策门 | 期望 |
| **O6** | 交付可运行系统 | 端到端 Demo 可演示；单图推理 <3 秒 | TG5 决策门 | 期望 |
| **O7** | 验证鲁棒性 | 在低光/雨雾/模糊/小目标条件下报告完整性能衰减曲线 | 实验报告 | 期望 |
| **O8** | 完成学术产出 | 论文/技术报告定稿；答辩通过 | 导师与评审 | **必达** |

> **优先级说明**：「必达」项失败即视为项目未达标；「期望」项失败可通过降级路径（见 `05-技术路线图-CN.md` §6）处理，需在报告中说明。

### 3.3 明确的非目标

以下**不属于**本项目成功标准，避免范围膨胀：

- ❌ 实时视频流的生产级部署
- ❌ 与现有施工管理系统（BIM / ERP）的集成
- ❌ 商业化产品开发与市场验证
- ❌ 硬件设备（摄像头、UAV）的采购与部署
- ❌ 覆盖全部电信施工工种与全部风险类型

## 4. 项目范围

### 4.1 范围内 (In Scope)

| 类别 | 内容 |
|------|------|
| **风险维度** | 地形（Terrain）、机械（Machinery）、材料（Materials）、人员（Workers，含 PPE 与不安全行为） |
| **场景** | 通信基站、格构式/单管铁塔、光缆沟槽开挖、楼顶天线、机房作业 |
| **输入形态** | 手持照片、固定摄像头图像（视频为期望项） |
| **技术** | 生成式 AI 数据增广、深度学习目标检测/分割、信息融合风险评估 |
| **交付** | 数据集、模型、pipeline 代码、Demo 系统、实验报告、论文/技术报告 |

### 4.2 范围外 (Out of Scope)

| 类别 | 说明 |
|------|------|
| UAV 航拍输入 | 列为 H3 延伸方向，非本期交付 |
| 塔上作业记录仪 | 同上，需额外设备 |
| 生产环境部署与运维 | 仅交付原型 |
| 多语言/多地区法规适配 | 规则库仅覆盖 OSHA 1926 与 GB 26859 等选定标准 |
| 传感器/IoT 数据融合 | 仅做图像内的多维融合 |
| 边缘设备优化 | 列为 H3 |

### 4.3 范围界定的关键决策 ⚠️

> **在四个风险维度上平均用力，在一学期内几乎不可能全部做到高质量。**
>
> **建议**：M0 阶段即明确「主攻 Workers + Machinery（必达 O4），Terrain 与 Materials 做到可用即可」，并在最终报告中诚实说明范围界定理由。
>
> 此决策须在首次团队会议上确认，并记入会议纪要。若选择四维全做，需在 §12 风险中相应提高 R7 的等级。

| R6 | 算力不足 | 中 | 中 | LoRA 而非全量微调；降级 D7 | 成员 B |
| R7 | 专家标注无法安排 | 中 | 中 | W8 提前启动；降级 D4 纯规则融合 | 成员 E |
| R8 | 文献引用未核实导致学术不规范 | 中 | 中 | 按 `04` §8 核实状态表逐条补全 | 队长 |

> **R2 与 R5 是两个"极高影响"风险**：前者动摇项目的核心学术主张，后者违反项目的硬性规定。这两项须在每次周例会上例行确认状态。

## 13. 变更控制

### 13.1 需要走变更流程的情形

- 项目目标（§3）的增删或成功标准调整
- 范围（§4）的实质性变化，包括触发任一降级路径 D1–D8
- 里程碑日期（§6）延后超过 1 周
- 交付物（§5）的删减
- 团队角色或队长的更换

### 13.2 变更流程

```
1. 提出   任何成员填写变更申请（背景 / 变更内容 / 影响分析 / 替代方案）
2. 评估   队长组织评估：对进度、交付、其他模块的影响
3. 表决   周例会全队表决（多数决）
4. 批准   涉及范围或目标变更的，须导师书面确认
5. 记录   更新本章程版本号；变更记入 §15 变更日志
6. 通知   队长同步全体成员与导师
```

### 13.3 无需走流程的情形

- 技术实现细节的调整（如换用不同的检测器）
- 周内任务顺序调整
- 未影响交付物的内部接口修改（但需通知下游成员）
