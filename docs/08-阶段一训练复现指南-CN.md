# TelecomSafe 阶段一训练复现指南

> 文档版本：v2.0 ｜ 编写日期：2026-09-29 ｜ 修订：2026-10-06（baseline v2：加入 Work at Height、E2 跑 3 个种子）
> 英文对照版：[08-Phase1-Training-Guide-EN.md](08-Phase1-Training-Guide-EN.md)
> 适用对象：需要从零复现阶段一结果的组员，或以后重新训练的自己
> 复现目标：得到 E1 / E2 模型权重、`reports/phase1/` 下的全部报告与图表，并能启动 Demo
> 结果说明见 [reports/phase1/README.md](../reports/phase1/README.md)；只想用现成模型、不想训练的话，直接看[第 9 节](#9-只想用现成模型)

## 0. 总览

**整体流程**：先用覆盖最全的两个数据集训练一个 teacher，由它给其余数据集补上缺失类别的伪标签，再合并出完整训练集，最后训练 E1 / E2 并评估。

```
下载数据 → 构建 teacher 数据集 → 训练 teacher → 生成伪标签 → 构建完整训练集 → 训练 E1 → 训练 E2 × 3 个种子 → 评估 → Demo
 (~25 分钟)     (<1 分钟)          (~12 分钟)    (~5 分钟)      (~2 分钟)        (~35 分钟) (~3.7 小时)        (~3 分钟)
```

以上耗时基于 RTX 4070 SUPER（12 GB），GPU 部分合计约 4.5 小时；只跑一个种子的 E2 约 2 小时。

**参考结果**（baseline v2，验证集 747 张，用于核对复现是否成功）：

| 实验 | mAP50 | mAP50-95 | 训练轮数 |
|---|---|---|---|
| E1（关闭增广，种子 0） | 0.596 | 0.326 | 第 41 轮早停 |
| E2（默认增广，种子 0 / 1 / 2） | 0.737 ± 0.007 | 0.451 ± 0.002 | 第 89 / 79 / 100 轮结束 |

在同一台机器、同样的软件版本下，同一个种子的结果应当完全一致；换了 GPU、驱动或库版本，允许有约 ±0.01 的差异。v1（2026-09-29，未含 Work at Height）的结果见 `reports/phase1/v1/`。

**⚠️ 三条硬约束**（改了就与现有结果不可比）：
1. **不要修改 `configs/baseline.yaml`**。阶段二的 E3 必须沿用同一份配置、只改训练数据。
2. **Construction Site Safety 必须用 Roboflow 的 version 30**，不要用 Kaggle 镜像。Kaggle 版的训练集全部是马赛克增广拼图，原因见 [progress/milestones.md](../progress/milestones.md) 的范围变更记录。
3. **TelecomEval 冻结后不要改动**。它建好之后，所有正式评估都以它为准。

## 1. 准备环境

**硬件**：NVIDIA GPU，显存 ≥ 8 GB（12 GB 可以按默认配置 batch 16 训练），驱动需支持 CUDA 13。磁盘至少留 3 GB 给数据与训练结果。

**创建环境**（在 Anaconda Prompt 或 PowerShell 中，于项目根目录执行）：

```powershell
conda env create -f environment.yml
conda activate telecomsafe
python -c "import torch; print(torch.cuda.is_available(), torch.cuda.get_device_name(0))"
pytest            # 单元测试，约 2 秒；不需要 GPU 与数据
```

第三行应输出 `True` 和你的显卡名。本文所有命令都默认**在项目根目录、`telecomsafe` 环境已激活**的前提下执行。

阶段一结果所用的版本：Python 3.12、PyTorch 2.14.0+cu130、Ultralytics 8.4.164。

> 在 Git Bash 里 `conda` 不在 PATH 上：可以改用 Anaconda Prompt，或者直接调用环境里的 Python，例如 `~/.conda/envs/telecomsafe/python.exe -m telecomsafe.train ...`。

## 3. 获取数据

### 3.1 自动下载

```powershell
python -m telecomsafe.data.download --list     # 查看各数据集是否已在本地
python -m telecomsafe.data.download            # 下载所有启用且能脚本化的数据集
```

### 3.2 手动放置 APD

APD 是他人分享的私有数据，不能公开下载。从**组内共享文件夹**取得 `APD.v1i.yolov8.zip`，解压到 `data/raw/apd/`，解压后该目录下应直接有 `train/`、`valid/`、`test/`、`data.yaml`。

### 3.3 核对

执行 `python -m telecomsafe.data.download --list`，下面 6 个都应显示 ✓：

| 数据集 | 本地目录 | 原始张数 | 获取方式 |
|---|---|---|---|
| Construction Site Safety v30 | `data/raw/construction_site_safety/` | 717 | Roboflow（自动） |
| Ultralytics Construction-PPE | `data/raw/construction_ppe/` | 1,416 | Ultralytics（自动） |
| body_harness v5 | `data/raw/body_harness/` | 796 | Roboflow（自动） |
| construction safety v2 | `data/raw/construction_safety_v2/` | 1,206 | Roboflow（自动） |
| Work at Height Safety v1 | `data/raw/work_at_height/` | 12,712（约 760 MB） | Roboflow（自动） |
| APD | `data/raw/apd/` | 2,300 | 组内共享（手动） |

Work at Height 只用含安全带的图（`sources.yaml` 中 `filter: has:harness`），并按 [`configs/exclude/work_at_height.txt`](../configs/exclude/work_at_height.txt) 剔除 862 张镜像填充的图，构建时自动完成。

然后运行 `python -m telecomsafe.data.catalog`，重新生成 [data/README.md](../data/README.md)，其中"本地原始张数"一栏应与上表一致。每个数据集的来源、许可和类别映射都登记在 `configs/sources.yaml`。

## 4. 构建 teacher 数据集

teacher 只用两个完整标注了"人员"的数据集训练。它学会所有类别后，再给其他数据集补上它们没有标注的类别。

```powershell
python -m telecomsafe.data.build --sources construction_site_safety construction_ppe --no-eval --no-pseudo --out data/processed/teacher
```

**预期输出**：`train: 1802 images`、`val: 200 images`、`Removed: {'duplicate': 131, ...}`

---

## 5. 训练 teacher

```powershell
python -m telecomsafe.train --exp teacher --data data/processed/teacher/dataset.yaml --epochs 50
```

- 约 12 分钟；结束时验证集 mAP50 ≈ **0.733**
- 权重保存在 `runs/phase1/teacher/weights/best.pt`

---

## 6. 生成伪标签

```powershell
python -m telecomsafe.data.pseudo_label --weights runs/phase1/teacher/weights/best.pt
```

对每个数据集，只补它**没有标注**的类别，置信度 ≥ 0.5 才采用，真实标注永远不会被覆盖。结果写入 `data/interim/pseudo/<数据集>.json`。

**预期伪标签数量**：

| 数据集 | 补出的框数 | 主要补的类别 |
|---|---|---|
| apd | 3,892 | 人员 |
| body_harness | 1,743 | 安全帽、反光衣 |
| construction_safety_v2 | 1,565 | 反光衣 |
| work_at_height | 11,297 | 反光衣、未穿反光衣、未戴安全帽、车辆（全部 12,712 张都会补，构建时只用其中含安全带的图） |
| construction_ppe | 0 | teacher 训练时见过这些图，没有补出原本缺的类别，属已知局限 |
| construction_site_safety | 0 | 只缺安全带，teacher 不认识这一类 |

## 7. 构建完整训练集

```powershell
python -m telecomsafe.data.build --dry-run    # 先看统计，不写文件
python -m telecomsafe.data.build              # 正式写出 data/processed/yolo/
```

这一步会依次完成：类别映射、合并伪标签、过滤与排除清单、感知哈希去重（包括与已选定的 TelecomEval 图去重）、按数据源分层切分出训练集和验证集（90 / 10，固定随机种子）。

**预期输出**：`train: 6728 images`、`val: 747 images`、`Removed: {'eval_leak': 0, 'duplicate': 1059}`；同时写出 `reports/phase1/dataset_stats.csv` 和 `coverage.csv`。

TelecomEval 还没建好时，命令行会提示"no test split"，这是正常的。

可选：`python -m telecomsafe.data.audit` 会为每个数据集随机抽 50 张画出标注框，保存到 `runs/audit/`，方便人工检查映射是否正确。

## 8. 训练 E1 / E2 并评估

### 8.1 冒烟测试（推荐先跑，约 1 分钟）

```powershell
python -m telecomsafe.train --exp e1 --name smoke --epochs 1 --fraction 0.05
```

能跑完、生成 `runs/phase1/smoke/`，就说明环境和数据都没问题。之后删掉 `runs/phase1/smoke/` 即可。

### 8.2 E1：关闭全部内置增广

```powershell
python -m telecomsafe.train --exp e1
```

- 约 35 分钟，本次在第 41 轮早停（`patience 20`）
- 核对：`runs/phase1/e1/args.yaml` 里 `mosaic`、`fliplr`、`hsv_h` 等增广参数应全部为 `0.0`

### 8.3 E2：Ultralytics 默认增广

```powershell
python -m telecomsafe.train --exp e2                          # 种子 0
python -m telecomsafe.train --exp e2 --seed 1 --name e2_s1
python -m telecomsafe.train --exp e2 --seed 2 --name e2_s2
```

- 每个种子约 1.1–1.4 小时，本次分别在第 89、79、100 轮结束
- 两个实验的配置都来自 `configs/baseline.yaml`（YOLO11s、640 px、batch 16），唯一的区别是 E1 关闭了增广；`--seed` 只换随机种子，用于估计结果的波动（报告均值 ± 标准差）

### 8.4 可选：YOLOv8s 对比（v1 数据上已完成）

```powershell
python -m telecomsafe.train --exp e2 --model yolov8s.pt --name e2_yolov8s
```

与 E2 使用完全相同的数据和配置，只换模型结构，用于论证模型选型。这项对比在 v1 数据上做过，结果保存为 `runs/phase1/v1_e2_yolov8s`；baseline v2 没有重做。

### 8.5 可选：YOLO11m 对比与输入尺寸试验

```powershell
python -m telecomsafe.train --exp e2 --model yolo11m.pt --name e2_yolo11m
```

同样只换模型，用于论证模型规模（v1 数据，`runs/phase1/v1_e2_yolo11m`）。冻结 v2 前另做了一次输入尺寸试验：

```powershell
python -m telecomsafe.train --exp e2 --imgsz 960 --name e2_960
```

约 2.3 小时，显存约 9.7 GB（batch 16）。两项的结果与结论见成果总结，均未采用。

### 8.6 评估

```powershell
# TelecomEval 建好之前：在验证集上评估（结果只作开发参考）
python -m telecomsafe.evaluate --split val --skip-check      # 默认评估 e1、e2、e2_s1、e2_s2
python -m telecomsafe.evaluate --exps e2 e2_960 --split val --skip-check --out <文件夹>   # 试验类对比，写到别处

# TelecomEval 冻结之后：正式评估（会先核对 TelecomEval 有没有被改动）
python -m telecomsafe.evaluate
```

**输出**（都在 `reports/phase1/`）：

| 文件 | 内容 |
|---|---|
| `<训练>_metrics.csv` | 每次训练的 mAP50、mAP50-95、Precision、Recall |
| `summary.csv` | 每个实验的汇总；名为 `<实验>_s<k>` 的训练算作该实验的其他种子，给出均值与标准差 |
| `per_class_ap.csv` / `per_class_ap.png` | 逐类 AP 表与对比柱状图（多个种子时为均值，柱上画标准差） |
| `<实验>_confusion_matrix.png` | 归一化混淆矩阵 |
| `class_distribution.png` | 训练集各类别实例数 |
| `weak_classes.md` | 弱类别清单。**文件已存在时不会被覆盖**，因为"可能原因"一列是手写的；需要重新生成时加 `--rewrite-weak-classes` |

训练日志最后一行的 mAP（以 v1 为例，E1 显示 0.605）与评估脚本的结果（0.611）会有细微差别，这是两者验证时的批处理设置不同造成的。报告统一以评估脚本的结果为准。

### 8.7 启动 Demo

双击项目根目录的 `start_demo.bat`，或者：

```powershell
python -m telecomsafe.demo.app --weights runs/phase1/e2/weights/best.pt --open
```

浏览器打开 http://127.0.0.1:7860。页面自带 5 个示例（`reports/phase1/demo_examples/`），预期风险等级依次为：低 / 中 / 高 / 低 / 低（最后一张是有意保留的失败案例）。

## 10. 一次性顺序执行

数据准备好之后（第 3 节），下面这些命令按顺序执行就能完整复现，约 4.5 小时（只跑种子 0 约 2 小时）：

```powershell
python -m telecomsafe.data.build --sources construction_site_safety construction_ppe --no-eval --no-pseudo --out data/processed/teacher
python -m telecomsafe.train --exp teacher --data data/processed/teacher/dataset.yaml --epochs 50
python -m telecomsafe.data.pseudo_label --weights runs/phase1/teacher/weights/best.pt
python -m telecomsafe.data.build
python -m telecomsafe.train --exp e1
python -m telecomsafe.train --exp e2
python -m telecomsafe.train --exp e2 --seed 1 --name e2_s1
python -m telecomsafe.train --exp e2 --seed 2 --name e2_s2
python -m telecomsafe.evaluate --split val --skip-check
```

重新跑之前，先删除旧的训练结果：`runs/phase1/{teacher,e1,e2,e2_s1,e2_s2}`。训练脚本会覆盖同名目录里的日志，但残留的权重文件容易造成混淆。

## 11. 常见问题

| 现象 | 原因与解决 |
|---|---|
| `CUDA out of memory` | 显存不够：训练时加 `--batch 8`。注意这会改变训练条件，结果须单独注明 |
| `torch.cuda.is_available()` 为 `False` | 装成了 CPU 版 PyTorch：`pip install --force-reinstall --no-deps torch torchvision --index-url https://download.pytorch.org/whl/cu130` |
| 构建时报 `ConfigError: class_map ... does not declare` | 数据集里出现了 `configs/sources.yaml` 没有登记的类别：按报错提示把它映射到目标类别，或映射为 `null`（丢弃） |
| `FileNotFoundError: [WinError 3]` | Windows 路径过长：构建脚本已缩短输出文件名；仍出现时，把项目移到更短的路径下 |
| 输出里 ✓ ≈ 等符号报编码错误 | 设置 `set PYTHONIOENCODING=utf-8`（PowerShell：`$env:PYTHONIOENCODING="utf-8"`） |
| Kaggle 报认证失败 | 检查 `.env` 里的 `KAGGLE_API_TOKEN`；阶段一其实不依赖 Kaggle，可以忽略 |
| Roboflow 下载失败 | 检查 `ROBOFLOW_API_KEY`；`configs/sources.yaml` 里固定了版本号，不要改成 `null`，否则会下到最新版本 |
| Demo 提示端口 7860 被占用 | 已经有一个 Demo 在运行：关掉之前的窗口，或加 `--port 7861` |
| 数据加载卡住，或反复启动子进程 | Windows 多进程的限制：训练入口已经处理；自己写脚本调用训练时，要把代码放在 `if __name__ == "__main__":` 里 |

## 12. TelecomEval 建好之后

TelecomEval 正在标注，进度见 [progress/milestones.md](../progress/milestones.md#暂缓事项)。标注并冻结后：

训练集**不会**因此改变：构建时已经与已选定的 TelecomEval 图（许可清单中审阅保留的 telecom / near 图）去重，所以 baseline v2 不需要重训。`configs/baseline.yaml` 已于 2026-10-06 冻结（tag `phase1-baseline-v2`）。
