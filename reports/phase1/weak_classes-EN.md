# Weak Classes (Phase 2 Generation Targets)

> 中文版：[weak_classes.md](weak_classes.md)

The 4 classes with the lowest E2 AP50 (mean over 3 seeds) on the validation split. Phase 2's (M3) risk-scenario specification library covers these classes first.

> ⚠️ These are **validation-split** results (TelecomEval is being annotated, see progress/milestones-EN.md). The validation split comes from the same sources as training, so the numbers are optimistic;
> re-evaluate the same models once TelecomEval is frozen before finalising this list.
> The Chinese file's table is generated by `python -m telecomsafe.evaluate --rewrite-weak-classes` and its "likely reasons" column is written by hand; this English version is translated by hand and must be updated alongside it.
> The v1 list (2026-09-29) is in [`v1/weak_classes-EN.md`](v1/weak_classes-EN.md).

| Rank | Class | AP50 | Training instances | Likely reasons (by hand) |
|---|---|---|---|---|
| 1 | vehicle | 0.399 ± 0.047 | 244 | The smallest class (real labels only from Construction Site Safety); high intra-class variety (cars, trucks, buses and trailers merged); only 33 validation instances, the largest seed-to-seed variation |
| 2 | no_helmet | 0.417 ± 0.009 | 1047 | Small targets (head only); hard to tell from heads wearing ordinary caps / headscarves; datasets differ in how they box a missing helmet (head box vs person box). A 960 input barely helps (+0.009), so resolution is not the only problem |
| 3 | machinery | 0.797 ± 0.014 | 762 | Few samples; the added aerial work platforms help machinery overall, but cable-laying vehicles, cable-drum trailers and bucket trucks common in telecom work are still almost absent |
| 4 | no_vest | 0.801 ± 0.010 | 4234 | Defined by an absence rather than a visible object, so torso box boundaries are subjective; mostly from APD, whose style differs from the other sources |

## Classes that need a special note

- **harness**: with Work at Height added in v2, training instances rise from 143 to 2,619, and validation AP50 goes from v1's 0.984 (13 instances, not trustworthy) to 0.814 ± 0.006 (285 instances, trustworthy), so it is no longer in the table. But Work at Height is mostly scaffolding and aerial platforms; on the 167 telecom construction candidates E2 detects a harness in only 26 images (v1: 0), and in the Demo the harness on pole workers scores only 0.20–0.22. **Harnesses in telecom scenes (tower and pole climbing) remain a key phase 2 target**, to be confirmed on TelecomEval.

## Recommendations for phase 2

Generation priority: **vehicle ≈ no_helmet > harness in telecom scenes > machinery (telecom-specific vehicles and equipment) > no_vest**.

- vehicle, machinery: add vehicles and telecom-specific vehicles to empty ground in real images (inpainting);
- no_helmet: remove helmets in real images (inpainting, the most reliable label inheritance);
- harness in telecom scenes: move harnessed workers onto tower and pole backgrounds (scene transfer).
